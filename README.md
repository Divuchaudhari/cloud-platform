\# Enterprise Cloud Platform: Self-Service Infrastructure on AWS



A portfolio project showing how a central platform team can let application teams provision standardized, secure AWS infrastructure through Git instead of opening tickets.



\## The problem



With 50-100 application teams, a central DevOps team that creates VPCs, containers, databases, IAM and monitoring by hand becomes a bottleneck. The result is slow delivery, inconsistent setups, excessive privileges and hard-to-audit changes.



\## The solution



Infrastructure is defined as code in Git. Every change goes through a pull request where automated checks validate, scan and preview it before anything reaches AWS. CI authenticates to AWS with short-lived OIDC credentials, so no AWS keys are stored in GitHub.

\## Security controls



\- GitHub OIDC with a repo-scoped trust policy, no stored credentials

\- Checkov scan on every pull request, with documented risk acceptances

\- KMS encryption, S3 public access block and versioning

\- Databases in private subnets with no public access

\- Passwords generated by Terraform or managed by RDS, never written in code

\- Terraform state in an encrypted, versioned S3 bucket with locking



\## FinOps



Every resource gets five tags through the provider's `default\_tags`: `Application`, `Environment`, `Owner`, `CostCenter`, `BusinessUnit`. These make per-team cost reporting possible once the tags are activated as cost allocation tags in AWS Billing.



\## Designed but not implemented



\- Reusable, versioned Terraform modules (each folder is a working reference to extract from)

\- OPA policy-as-code to enforce tags and approved regions

\- EKS

\- Multi-account strategy and disaster recovery

\- Automatic apply after merge with an approval gate

\- Least-privilege scoping of the CI role, which currently uses broad AWS-managed S3 and DynamoDB policies



\## Problems solved along the way



1\. \*\*OIDC "Not authorized" error:\*\* GitHub puts account and repo IDs in the token's `sub` claim, and pull request tokens end in `:pull\_request`. Fixed by widening the trust policy patterns.

2\. \*\*State lock `AccessDenied`:\*\* the CI role had S3 access but no DynamoDB permission.

3\. \*\*Checkov fix cascade:\*\* adding a KMS key raised a new finding for a missing key policy.

4\. \*\*Alarm did not fire:\*\* the test log line carried a timestamp from days earlier.



\## Cost discipline



Hourly-billed resources (NAT gateway, Fargate, RDS) were created for testing and destroyed afterward.
